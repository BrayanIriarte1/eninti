0:003 min

Introducción: problema, solución y arquitectura

Rachel
  • El problema: ENINTI lleva suscripciones y mantenciones en planillas y mensajería (~100 plantas).
  • La solución: plataforma web con tres perfiles (cliente, técnico y administrador), cobro recurrente en sandbox y plan base de $15.000 mensuales.
  • Mostrar la topología: React (Vite, 5174) → API Express /api (3001) → PostgreSQL eninti. Monolito modular: rutas → controlador → servicio → datos.
  • Mostrar los dos diagramas de casos de uso y anunciar el recorrido.

Qué decir«Vamos a seguir a una clienta nueva desde que pide su cuenta hasta que se le cobra la cuota, pasando por los tres perfiles. Cada pantalla corresponde a un caso de uso del diagrama.»

Revisar que la suscripción tenga día de cobro 1 y que la tarjeta esté inscrita; usar «Operaciones manuales» → «Reintentar cargos ahora».
